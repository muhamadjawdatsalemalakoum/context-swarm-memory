# AUDIT 2026-09-05 — findings report

Full-repository audit of Context Swarm Memory: every layer of `src/`,
`scripts/`, `tests/`, `integrations/`, `docs/` and the repo config, against the
ten architecture invariants in `CLAUDE.md` and against every number the project
publishes under the author's name.

- **Scope:** 14 layers, 25 finder passes, **383 de-duplicated candidates**.
- **Acted on:** 12 fix units, commits `dc2629b..HEAD` (14 commits).
- **Result:** **4 of the 10 invariants were violated**, a 5th was overstated;
  7 published numbers were wrong or unqualified; 8 run-integrity defects could
  have silently corrupted a benchmark run.
- **Raw candidate list:** [`AUDIT-2026-09-05-CANDIDATES.md`](AUDIT-2026-09-05-CANDIDATES.md).
- **Current claim set after the fixes:** [`../STATUS.md`](../STATUS.md).

> **A caveat about this audit's own reliability, stated first.**
> Agent-side adversarial verification was killed twice by usage limits, so
> **no finding here was auto-verified**. Everything in Parts 1–5 was checked by
> hand against the code or the artifact before it was touched — but that is a
> weaker guarantee than a 3-refuter majority, and the 97 `unaddressed`
> candidates in the appendix carry **no verification at all**. Treat them as
> pointers, not findings. This section exists because an audit that hides its
> own limits is the thing it is supposed to catch.

## Part 1 — Findings that changed a published number

These are the ones that matter most: each was live on the README, the GitHub
Pages site, `llms.txt`, or `EVIDENCE.md` under the author's real name.

### 1.1 The hybrid-router evidence predates the render-gap fix — HIGH

`+0.365 answer at 1M, 26W/5L` was cited on every surface as the reason
`CSM_ROUTER_HYBRID` is default-ON, and as "the strongest single effect measured
on this project".

It was measured on sidecar arm **r1mC (2026-07-31)**, and
`EXP-capsule-render-gap.md` lists r1mC among the arms graded on
**CSM-minus-capsule** — the harness rendered the evidence capsule as a
placeholder string for *both* arms. The delta is within-harness valid; the
absolutes (0.418 → 0.782) are not, and it has **never been re-measured with the
capsule rendered**.

*Fixed:* the caveat now travels with the number on README, STATUS, site,
`llms.txt`, `EVIDENCE.md` and `PREFLIGHT_OFFICIAL_LADDER.md`. Every post-fix
certified arm runs with the router ON, which is indirect support and is labelled
as such.

### 1.2 That result was attributed to the wrong instrument — HIGH

`EVIDENCE.md`'s lever ledger recorded the router row as **"gemini, 1M ladder"**.
The arm's own `config.json` says `providerName: "agent-sdk"` — the Claude
sidecar. The June Gemini ladder ran with the router **OFF**.

*Fixed:* attributed to the sidecar slice arm r1mC, with a note that the June
ladder ran router-OFF.

### 1.3 "Fold, never append" was an absolute; the code makes it conditional — HIGH

README, the site and `llms.txt` all stated the invariant as unconditional, with
"displacement measured fatal four separate times" as the justification.

`scripts/amb-csm-retrieve.ts:578` emits the fact registry as a **standalone
document** when no evidence capsule exists — which is the common case for point
queries, i.e. most `knowledge_update` and `abstention` questions, i.e. the
categories the certified leads come from.

*Fixed:* restated as the conditional rule it is on all three surfaces. Every row
now carries `factFoldMode` (`off` / `replace` / `folded` / `standalone` /
`unavailable`) so the branch taken is visible per query.

### 1.4 The head-to-head reader silently truncated CSM's context — HIGH

`scripts/headtohead-arms.ts` cut the reader's context at **200,000 characters**
with no count and no record. Measured against the certified arms on disk:

| arm | rows over the cap | worst case |
|---|---|---|
| 500K certified pair | **1 of 140** | `28_information_extraction_1`, 371,482 → 200,000 chars (**46% dropped**) |
| 1M paired fold arm | **1 of 70** | `34_knowledge_update_1`, 214,681 → 200,000 |
| Hindsight, either tier | **0 of 700** | max 119,065 chars — never reaches the cap |

The cut is **asymmetric against CSM**, so the certified leads are if anything
conservative. But a cut the output does not record is a defect.

*Fixed:* every truncation is counted and written into the result JSON, along
with per-query exclusion reasons and SHA-256 provenance of both input artifacts.
Disclosed in STATUS and `llms.txt`.

### 1.5 The 10M span figure was wrong twice — HIGH

Published as **98–99.9%** of each unit's turn range, as the empirical
counter-evidence to the upstream report of a `~0.27%`-loaded 10M corpus. That
number was never computed by any committed script — it was recalled.

| version | span coverage | ref density | why |
|---|---|---|---|
| originally published | 98–99.9% | — | recalled, never computed |
| first correction (2026-08-30) | 64.3–89.7% | 11.6–15.9% | computed, but the regex matched only the ~100 **dated** turn markers per unit (`[July-01-2024 ¦ Turn 0]`) rather than all ~19,900 (`[Turn N]`) |
| **correct (2026-09-05)** | **63.5–88.8%** | **11.5–15.8%** | matches both marker shapes |

*Fixed:* `scripts/measure-hindsight-10m-span.mjs` computes it from primary
artifacts and prints the dated-marker count so the discrepancy is visible in its
own output. The conclusion survives — reaching across 63–89% of a unit's
timeline is still hard to reconcile with a 0.27%-loaded corpus — but the number
was wrong by a wide margin, twice.

### 1.6 The judge calibration is against a judge that no longer exists — MEDIUM

"Calibrated ρ 0.864 / MAE 0.077 **against the official judge**" appears on every
surface as the reason the free instrument can be trusted.

That calibration is against the **pre-PR-#20** judge — `gemini-2.5-flash-lite`,
rubric-fraction scoring with Kendall τ-b for `event_ordering`. Upstream replaced
it with a nugget judge. **The calibration has not been redone.**

*Fixed:* scoped on STATUS, `llms.txt` and `EXP-judge-calibration.md`.

### 1.7 Six more claims that were false or unqualified — MEDIUM

| claim | reality |
|---|---|
| "unmodified public AMB runner … a **3-file** CSM provider and nothing else" | `npm run amb:patch` also edits **two upstream files**: registers the provider in `memory/__init__.py`, adds `OMB_GEMINI_TIMEOUT_MS` to `llm/gemini.py`. ## Part 2 — Invariant violations

`CLAUDE.md` states ten architecture invariants. Four were violated in code and
one was overstated in prose.

### 2.1 Invariant 5 — "unrecognised config is an error, never a default" — VIOLATED

The invariant exists because `CSM_ROUTER_HYBRID=off` once turned the router
**ON**. The audit found the same class alive in **14 environment variables**
across 13 resolver functions, every one silently falling back to its default on
garbage:

`CSM_RECALL_BUDGET`, `CSM_MAX_PROBE_SHARDS`, `CSM_MAX_RECALL_SHARDS`
(`tokenBudget.ts`) · `CSM_COVERAGE_RECALL_TOKENS`, `CSM_COVERAGE_MAX_ENTRIES`,
`CSM_COVERAGE_STARVATION_FLOOR` (`coverage.ts`, via a private
`parsePositiveInt`) · `CSM_RETRIEVAL_UNITS` · `CSM_SHARD_EXPAND_K/_MAX`,
`CSM_LEXICAL_BRIDGE_K/_MAX`, `CSM_ENTITY_BRIDGE_K/_MAX`
(`baselines/csm.ts`) · `CSM_VIRTUAL_SHARDS` (`amb-csm-retrieve.ts`).

Plus two enum readers:

- **`CSM_GEMINI_CACHE`** — warned once to stderr, then returned `"off"`.
- **`CSM_PROVIDER`** — the worst one. A typo like `gemni` fell through the
  explicit-match list into URL auto-detection and landed on **`"mock"`**. An
  entire benchmark run could execute against the deterministic stub provider
  with nothing in the output saying so.

And **five tests pinned the silent behaviour** — including
`gemini_cache_mode_defaults_off_and_rejects_unknown`, which asserted the exact
opposite of its own name, and `embeddingFloor.test.ts`, which called that shape
*"the exact shape the env.ts invariant exists to forbid"* eighty lines above
where it pinned it.

*Fixed (unit 2):* all routed through `envInt` / `envPositiveInt` / `envEnum`;
a present-but-invalid value now throws `EnvConfigError` naming the variable.
Where `0` is a meaningful "off" the resolver uses `min: 0`; where a count must be
positive, `0` throws too. The five tests now pin the throw.
New `tests/envIntegerResolvers.test.ts` tables every integer and enum resolver
outside `env.ts` — unset→default, valid→verbatim, zero→off-or-throw,
garbage→`EnvConfigError` — so a resolver not in the table is a resolver nobody
checked.

> *Footnote on my own accuracy:* the unit-2 commit message says "twelve"
> hand-parsed integer readers. The literal-name count is 12; the true count is
> **14**, because `resolveShardCount` covers `CSM_MAX_PROBE_SHARDS` and
> `CSM_MAX_RECALL_SHARDS` through a `name: key` parameter and my grep missed
> both. The commit message undercounts.

### 2.2 Invariant 4 — "a component that cannot discriminate must SAY so" — VIOLATED

`src/core/selection.ts:select()` has reported ranking degeneracy since it landed.
The audit found that on the production path, **nothing read the report**:

- `ask()` computed the `SelectionResult` for the router cut and the recall cut,
  used `.selected`, and **discarded** `discriminated` / `degenerateReason` /
  `signalRatio`. Neither `AskRunResult` nor `QueryRunRecord` had a field for it,
  so the operator was never told when a ranking was arbitrary.
- `hybridRouterStats()` — the hybrid router's "counted, not silent" fallback
  counter — had **no consumer anywhere outside tests**. No runner, manifest or
  report could see that a query fell back to the degenerate lexical ranking.
- **Six scored cuts never went through `select()` at all**: chronicle assembly
  Phase A and Phase B (`coverage.ts`, on the default-ON coverage path), the
  entity-bridge and lexical-bridge cuts (`baselines/csm.ts`), the bridge's
  coverage bucket cut (`amb-csm-retrieve.ts`), the salience reorder
  (`digestSelection.ts`), and the local probe pre-gate (`ask.ts`).

*Fixed (unit 3):* every cut routed through `select()` with its tiebreak stated
rather than inherited from sort mechanics (`"stable"` where the input was
pre-sorted chronologically; `key-desc` where the old code did `localeCompare`;
zero-padded numeric keys where it compared turn numbers) — **byte-identical
ordering**. The report is now surfaced three ways: `AskRunResult.selection`,
`QueryRunRecord.{routerDiscriminated, recallDiscriminated, degenerate[]}`, and
the bridge's `raw_response.meta` — which also gained `hybridRouterStats()` and
new chronicle degenerate-bucket counters.

### 2.3 Invariant 7 — "recall must cite shard, snapshot and event IDs" — VIOLATED

`RecallResult.shardId` and `.snapshotId` were copied from the **model's echoed**
`shard_id` / `snapshot_id`, and each claim's `support` event ids were taken on
trust. A model that echoed the wrong shard, or invented an event id, would have
had that cited downstream as fact. The invariant says citations must be
*correct*; correct means "the snapshot this call was actually made against".

*Fixed (unit 9):* ids come from the call. Support ids are filtered against the
snapshot's actual events. An echo mismatch and any dropped fabricated ids are
both recorded as explicit `conflicts`, so the discrepancy is visible rather than
silently corrected.

### 2.4 Invariant 6 — "no corpus-specific vocabulary in the retrieval path" — VIOLATED

The **live recall prompt**, sent on every recall call for every corpus, named a
PaySwift benchmark answer entity and the exact alias mapping that PaySwift MCQ
q11 tests:

> "If the question asks about a *dental-SaaS vendor* and the events describe
> *ChairSync, a dental-practice management software*, that IS a match."

*Fixed (unit 4):* replaced with a role/category example naming no entity. The
`ask.ts` comment that explained the router-trust net using the same entity is
anonymised.

### 2.5 Invariant 10 — "write-time artifacts fold, never append" — OVERSTATED

See §1.3. Real behaviour is conditional; documentation was absolute.

### The other five

Invariants **1** (query path never mutates), **2** (single durable-write entry
point), **3** (immutable snapshots), **8** (Zod on every LLM output) and **9**
(gold never reaches retrieval) were **upheld**. Two carried gaps worth noting:
invariant 2 had one undocumented exception (`csm init` appends the single `init`
chronicle record directly — now documented in `ARCHITECTURE.md`), and invariant
9's *filler leakage scan* was vacuous on a fresh checkout (§3.7).

## Part 3 — Run-integrity defects

Defects that could have silently corrupted or invalidated a benchmark run.

### 3.1 A dead warm server was respawned **empty** and kept serving — HIGH

`integrations/amb/csm_provider.py`: `retrieve()` called `_ensure_server()`,
which respawned a dead server holding **zero documents** and never replayed
`documents.jsonl` — the replay lived only in `prepare()`. Every remaining query
in the unit then returned `no_documents_in_scope` with **HTTP 200**. AMB recorded
them as ordinary wrong rows, the ladder counted them toward tier completion, and
`--skip-ingested` would then skip the unit as done.

*Fixed:* `_ensure_server()` reports whether it respawned; `retrieve()` replays
the durable log before serving and logs the respawn to stderr.

### 3.2 The 10M resume could never have worked — HIGH

The resume path POSTed the entire document log in **one request**. The server
caps bodies at **256 MiB**; the completed 10M store on disk is **329,246,098
bytes**. A `-SkipIngested` resume of a fully-ingested 10M tier would have failed
every time.

*Fixed:* replay batched at 48 MiB.

### 3.3 An empty write-time build was cached forever as a silent OFF — HIGH

`loadOrBuildFactRegistry` / `loadOrBuildPreferenceProfile` treated **any**
existing cache file as a hit and persisted whatever the build returned —
including empty text. One empty build (throttle, timeout, extractor hiccup) was
written to disk and read back forever as a valid artifact: the **certified
`knowledge_update` lever** silently and permanently off for that
`split|user|model` key, with no marker anywhere.

**Four zero-byte registries were sitting in the real cache directory.**

*Fixed:* a 0-byte or whitespace-only cache file is a miss and is logged; an empty
build result is never written. The four files were removed.

### 3.4 A failed fold build was indistinguishable from fold-OFF — MEDIUM

When the registry build failed, the query was graded **without the certified
lever** and nothing in the row said so: `factBuildCost` is null on the fold path
either way, and `evidenceCapsule` is true whenever any capsule exists.

*Fixed:* the server passes `factRegistryStatus`
(`off` / `available` / `build-failed`); every `raw_response` carries it plus
`factFoldMode`.

### 3.5 The watchdog could not actually recover the ladder — HIGH

`run-beam-watchdog.ps1` relaunched the ladder **without the now-mandatory
`-Tag`**, so the relaunched PowerShell blocked forever on the parameter prompt in
a hidden window — while step 1 kept reporting "ladder alive" because the blocked
process matched. Its tier list was also hardcoded to the **completed June run
dirs**. The recovery mechanism was the thing that could not recover.

*Fixed:* the ladder records its tag to `data/eval/runs/ladder-current-tag.txt`;
the watchdog reads it, derives run dirs from it, passes it on relaunch, and
refuses to relaunch without one. Both guards now see `pwsh.exe` as well as
`powershell.exe`, and the ladder's worker kill matches `omb` as a **word**
rather than as the substring inside `comb` or `zombie`.

### 3.6 A resumed slice run overwrote its own provenance — MEDIUM

`run-beam-slice.ts` rewrote `config.json` on **every** invocation including
resumes, so a `payloads.jsonl` assembled across invocations under different env
or commits carried only the **last** invocation's `gitSha` / `envEcho` /
`resolvedLevers`. That is precisely the F7 failure shape the manifest exists to
prevent.

*Fixed:* the first manifest is immutable; each resume writes
`config.resume-<iso>.json` with `resumeOf` set.

### 3.7 Two gates that passed without checking anything — MEDIUM

- **`verify-no-leakage.ts`** scanned filler files that are **gitignored**, so on
  every fresh checkout it printed **"✓ Clean"** having read **zero events**.
  *Fixed:* zero events is now an explicit `SKIP` that says nothing was scanned.
- **`free-ladder-tier.sh`** did not check the head-to-head's exit status (unlike
  its emit step), so on failure it ran the report over whatever **stale**
  `<tier>-free.json` already existed. *Fixed.*

### 3.8 The report could "certify" at n=1 — MEDIUM

`free-ladder-report.mjs` certified on `|delta| > MDE` alone, dropping the CI
condition and the `n ≥ 2` guard that `headtohead-arms.ts` applies. At n=1 the
standard error is 0, so **any** nonzero delta was "certified".

*Fixed:* same rule as the head-to-head (n ≥ 2, clears MDE, CI excludes zero), and
`ci95` is now in the row.

## Part 4 — Correctness defects

### 4.1 The chronicle assembler collided events across shards — MEDIUM

`assembleChronicle` keyed four working maps (`byEventId`, `indexById`, `picked`,
and the token-cap `dropped` set) by the **bare event id**. But durable-store ids
are **per-shard sequences** — `commit.ts` issues `e_0001`, `e_0002` in *every*
shard. On any `csm ask` that probed ≥2 shards under coverage mode (default ON),
the assembler scored one shard's event against another shard's token set,
`picked` collapsed distinct events into one, and the drop set removed both twins
when it meant one.

*Fixed (unit 8):* all four keyed by `(shardId, eventId)`. Probe footholds arrive
as bare ids and now resolve to **every** shard that has them — the conservative
choice for probe-verified evidence — instead of silently to the first shard
alphabetically. The BEAM bridge path, whose ids are globally unique, is
byte-identical.

### 4.2 The Committer contradicted itself and ignored its own confirmation flag — MEDIUM

Three defects in `src/core/commit.ts` and the CLI:

- `dryRunCommit` returned **`wouldMutate: true`** for `split`, `merge`,
  `ask_confirmation` and any unrecognised action, while its own `description`
  said *"Would be a no-op"* — and `applyCommitDecision` then returned
  `applied: false`. A dry-run no caller could trust.
- **`CommitDecision.requiresUserConfirmation` was read by nothing.** A decision
  that asked for confirmation was applied unconditionally.
- The CLI cast `--action` and `--memory-type` with `as` and never validated
  them, so a typo produced a dry-run claiming a mutation and an apply that did
  nothing — **both exiting 0**.

*Fixed:* unimplemented actions report `wouldMutate: false`;
`applyCommitDecision` takes `confirmed?: boolean` and refuses without it (CLI:
`--confirm`); both flags validated against the closed vocabularies in `types.ts`,
exiting 2 with the accepted values.

### 4.3 A crashed append poisoned a shard permanently — MEDIUM

`appendEventAndSnapshot` writes the immutable snapshot before the manifest —
correct ordering — but a crash in between leaves an **orphan snapshot** that no
manifest references. The next append computes the same id, hits the storage
layer's overwrite refusal, and fails **forever**, with an error message that says
nothing about why.

*Fixed:* the orphan is detected and the error states what happened and how to
recover. Nothing is overwritten automatically.

### 4.4 The startup deadline could never fire — MEDIUM

`csm_provider.py` checked its readiness deadline only **between** `readline()`
calls, and `readline()` blocks. A child that stayed alive but printed nothing
hung `initialize()` indefinitely; `CSM_AMB_SERVER_STARTUP_TIMEOUT_SEC` never
fired.

*Fixed:* stdout is read on a thread into a queue polled with a timeout; the same
thread drains for the life of the process.

### 4.5 The eval harness counted failures as wrong answers — MEDIUM

`src/eval/runner.ts`:

- Errored cells were pushed into `cellScores` as `correct: false`, and
  `reconstructEarlyStops` counted error rows as incorrect. A burst of transient
  provider timeouts could **permanently early-stop** a `(system, ctx)` at a
  corpus size it never actually failed.
- On resume, `seen` correctly excluded errored rows so they'd re-run — but the
  **stale error row stayed in the in-memory results** alongside the fresh one, so
  `summary.json` double-counted the cell and disagreed with `bench replay`.

*Fixed:* errored rows are excluded from the in-memory results, from the live
early-stop aggregate and from the replayed one, and counted separately as
`cellsErrored`. `results.jsonl` on disk stays append-only and keeps the history.

### 4.6 Citation F1 mixed model-cited and system-inferred rows — MEDIUM

When the answer model emitted no `CITATIONS` line, `baselines/csm.ts` substituted
**every packed event id**, and the scorer computed citation precision/recall/F1
from that list. The substitution is a defensible choice — the system *did* use
those events — but published citation F1 then mixed the two populations with **no
way to tell them apart**.

*Fixed:* each row carries `meta.citationsInferred`. The substitution stays.

### 4.7 Three smaller ones — LOW

- **`cachedLlm.ts`** carried a comment promising to *"surface [an empty provider
  response] to the caller so the result row records the failure honestly"* — and
  surfaced nothing. `CachedLlmCallOutput` now has `refusedEmpty`.
- **`corpus.ts`** `sampleFromEvents` silently returned fewer tokens than
  requested once filler ran out, and the runner labelled the cell by the target
  it never reached — the default sweep goes to **1B** on a ~9M-token corpus. It
  now warns below 95% of target.
- **`run-beam-tier.ps1`**'s `.env` guard used `Write-Error` under
  `$ErrorActionPreference = 'Stop'`, which **terminates before `exit 2`**, so an
  intentional abort surfaced to the ladder as a retryable crash.
  `Write-Warning` + `exit 2`.

## Part 6 — Real, kept, and disclosed

**`HIGH_SIGNAL` in `src/core/digestSelection.ts`** is a hand-written English
business vocabulary (`decid`, `approv`, `launch`, `block`, `deadline`, `price`,
`reject`, `deny`, `chose`, `select`, `migrat`, `version`) that boosts fragment
retention in the recall digest. It is neither corpus-derived nor structural, so
it violates the letter of invariant 6.

It stays, because:

1. it is behind `CSM_SIGNALS_RANKER`, **default OFF** — not on the certified path
   and not in any published number; and
2. it was **measured** under that flag (BABILong task-1 needle 7%→100% @8K; no
   multi-hop gain). Silently rewriting a measured lever destroys the
   comparability of that record.

The header now says exactly this, and states that promoting the lever to a
default requires replacing the table with a corpus-derived signal and re-gating
first.

## Appendix A — Method, and what went wrong with it

**Design.** 14 layers × 1 mapper + 2 finder lenses (correctness/invariants;
drift/dead-code/security), then per-finding adversarial verification by 3
independent refuters with distinct lenses (re-read the code / is it deliberate? /
does it matter?), majority rules, **default-to-refute** — then a coverage critic
and repo-wide sweeps for anything a per-layer pass would miss.

**What actually happened.** The mappers and 25 of 28 finders completed. **The
verification phase was killed by usage limits twice**, on two separate days.

The first run's post-processing then did something worse than failing: it counted
a finding with **zero** verifier votes as *refuted*, and reported
`{confirmed: 0, refuted: 144}` — i.e. "nothing is wrong", from a run where
nothing had been checked. That is the same class of defect as the ones in Part 1:
a pipeline that produces a confident-looking number from an absent measurement.

**Fixed in the harness before the second attempt:** a finding with fewer than 2
verdicts is `unverified`, never `refuted`; and verification was restructured from
3 agents per finding (each re-reading the same 2,000-line file) to **one agent
per file per lens**, ruling on every finding in that file with full-file context
— roughly 430 agents down to ~150.

The second attempt died at the same phase. At that point I stopped trying to
automate it and verified by hand, class by class: invariant claims are
mechanically checkable by `grep`, drift claims are read-comment-against-code, and
only the correctness claims needed deep reading.

**Consequence for trust.** Parts 1–5 were hand-verified against code or
artifacts. That is weaker than a 3-refuter majority and it is worth saying so.

## Appendix B — Errors made during the audit itself

Recorded because the project's standard is that failures are published with the
same weight as fixes:

1. **A type error shipped in unit 11.** `cellsErrored` was added to a progress
   object without being added to the `ProgressTick` interface. Tests passed
   (vitest does not type-check) and the lint failure was **masked by piping
   `npm run lint` through `tail`**, which discards the exit code. Fixed in
   `66d0ace`; every later gate ran under `set -o pipefail`.
2. **A test asserted a fixture-dependent guess.** The first unit-3 test asserted
   that a specific query's router cut would be degenerate, rather than asserting
   the plumbing (report reaches result and record; degenerate cuts are named).
   Caught before commit and rewritten.
3. **The unit-2 commit message undercounts** the converted readers as twelve; the
   true count is fourteen (see the footnote in §2.1).
4. **A diagnostic hung for an hour.** An inline `npx tsx -e` probe with a
   top-level `await` never exited and had to be killed. Its question had already
   been answered by reading `select()` directly.
